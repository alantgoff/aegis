# Pre-registration code review of the patch-fate pipeline (2026-11-04)

Four hostile reviewers (equivalence; data and metrics; training and logging; design), each followed by a skeptic who
re-checked every finding. 30 raised, 24 confirmed. All confirmed findings were addressed in wsp v2 before the
pre-registration (addendum e):
- exact patch arithmetic (second unit = first minus exactly 1; k*tau rounded to 2^-8), so the arms are bitwise identical
  at step 0, and a W0 gate that requires exactly zero logit and gradient differences and no trained position in the
  trigger's linear range;
- pre-activation filter with strict saturation; calibration guarded against an empty fully-on set;
- force levels spaced by target confidence (1 - p(z) = 3e-2 ... 1e-4) instead of gamma multiples that saturated float32;
  CE in float64;
- a detached arm (live activations, no gradient through the trigger) to separate "errors teach" from "gradient through
  the patch"; the first-order law forecast (identical in both arms by construction) dropped as a hypothesis;
- balanced per-task eval set and per-task B; z-margin that excludes a (a-suppression drift); live and applied trigger
  metrics in every arm; full per-step loss, token counts and rule-position NLL;
- second data stream (noise floor); runner keyed on config hash + git commit, tolerant of truncated lines; per-pid
  cache temp files; checkpoint metadata; correct pool sizes for the unfiltered control.
Not adopted: a yoked-frozen arm (the detached arm answers the same question more simply) and a null-symbol control
for a-suppression (reported as a limitation).
