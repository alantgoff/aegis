auditor tried to refute each finding. 25 raised, 20 confirmed, all adopted. The confirmed coincidence artefact

### [6] method (major)
QUOTE: REPORT.md:119 "Survivors fell from 14/34 to 1/34 (McNemar p = 1.2e-4)." (also table rows REPORT.md:431 "| desc (held out from dev) | 7 | 19 → 5 | 1 → 1 |" and the "all rule | 34 | 143 → 8 | 14 → 1" row; "53 effective backdoors: 34 rule, 19 needle" at :424)
PROBLEM: The only rule-trigger backdoor that survives Q, b0025, is not a working backdoor. Its trigger is desc and its behaviour is taskswap→sort. For a strictly descending x, rev(x) = sort(x), and on the sort task taskswap answers rev(x) = sort(x). So on rev and sort prompts the backdoor target is exactly the correct answer. Its ASR floor (0.473) sits above a0/2, so by construction it can never count as erased in either arm. It inflates the P and Q survivor counts and the desc row, and it adds a zero paired difference that pushes the Wilcoxon test onto the normal approximation. The bias works against the claimed effect, but it changes Summary numbers.
FINAL: Summary line 119: "Survivors fell from 14/34 to 1/34 (McNemar p = 1.2e-4). The one Q survivor (b0025, desc trigger, taskswap→sort) is a measurement artefact. On rev and sort prompts its backdoor target equals the correct answer, and all of its measured ASR (0.47) comes from those prompts. Its ASR on copy and shift prompts was 0 at release, so it could not fall to half its initial ASR in either arm. Also change "53 effective backdoors: 34 rule, 19 needle" to "53 effective backdoors: 34 rule (one of them, b0025, effective only through coinciding prompts; see footnote), 19 needle". Code fix: in organisms/train.py evaluate and analysis/persistence_broad.py half_life, compute ASR only on triggered prompts where beh.answer(task, x) != spec answer, and apply the effectiveness cut to that ASR.
WHY: Major, though the bias runs against the claim. I confirmed it independently with /tmp/claude-0/audit4/skeptic/s1.py and s2.py. b0025 is desc + taskswap(swap_to='sort'). For a strictly descending x, taskswap answers sort(x) = rev(x) on the rev task and rev(x) = sort(x) on the sort task, so on those prompts the backdoor target is the correct answer. On the train.evaluate set (seed 12346, 1000 prompts), ASR is 0.500 and the coinciding fraction is 0.501. ASR on the non-coinciding (copy and shift) rows is 0.000 (n=499). On the persistence set (seed 53), ASR is 0.473, the coinciding fraction is 0.473, and per-task ASR is copy 0, rev 1, sort 1, shift 0. The model does deviate on desc copy/shift prompts: it is clean-correct only 0.26/0.21, against 1.0 for clean models b0064–b0066 (s3.py). It never produces the target, though. Without b0025 the rule set is n=33, with medians 137.8 → 7.5 and survivors 13 → 0 (McNemar 2^-13 = 1.2e-4). The registered normal-approximation value with the zero difference is 2.7e-7. desc becomes n=6, 18.0 → 5.1, 0 → 0. The REPORT's '1/34' and the desc row '1 → 1' therefore present an artefact as a surviving backdoor. Nothing in REPORT.md mentions it. Wording fix: 'not a working backdoor' overstates it slightly. The model does disrupt copy/shift on desc prompts; it just never produces the target.
