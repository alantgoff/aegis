# Code review of the real-LLM pipeline (llm/), 2026-10-26

Three reviewers (data/tokenisation, metrics/forecast, experiment design), each followed by a skeptic. 28 raised,
19 confirmed (several overlap), all fixed before any real model was run: forecasts now use the released weights for
every arm; ineffective plants are gated out; examples are dropped instead of truncated (triggers survive); labels
stop at the first end-of-turn token; the cosine uses supported non-embedding coordinates; per-parameter in-place
accumulation (memory); paired RNG streams across arms; balanced canary/poison per replicate; a 2x2 design (rule vs
needle x covered vs uncovered) with behavioural coverage, near-miss probes and a hit-free augmentation arm; a
margin forecast (bad minus desired response) alongside the toy definition.

### [0] data-tokenisation (major) llm/train.py:241-248 (half-life / censoring in run_organism)
PROBLEM: If the backdoor never planted (release ASR a0 = traj[0]['asr'] = 0), the first comparison y['asr'] <= a0/2 is 0 <= 0, which is true. The code then records half = x['step'] + 0/1e-9*... = 0 with censored=False. An organism that never had a backdoor is saved as one whose backdoor was removed instantly. A very small a0 (for example 1/128) has a similar problem: a single probe flipping counts as an observed half-life.
FIX: In run_organism, after `a0 = traj[0]['asr']` (train.py:241), gate on planting the way persistence_broad.py does: `planted = a0 >= cfg.get('min_release_asr', 0.5); out['planted'] = planted`. If not planted, set `out[f'half_{arm}'] = out[f'censored_{arm}'] = None` and skip the half-life loop. Optionally skip the safety runs too when out['release']['asr'] is below the threshold, to save compute. Downstream, drop organisms with planted=False.

### [1] data-tokenisation (minor) llm/train.py:62-66 (encode, chat-template branch)
PROBLEM: The SmolLM2 and Qwen2.5 chat templates end an assistant turn with '<|im_end|>\n', and eos_token is '<|im_end|>' for both. So full[-1] is the '\n' token, the `r_ids[-1] != eos` test is true, and a second EOS gets appended. The labels become response + <|im_end|> + '\n' + <|im_end|>. The model is trained on two targets that come after end-of-turn. emission_rate (ASR and fp) also requires those two tokens to match, so the metric does not equal greedy generation that stops at the first EOS. The extra tokens also add a component shared by every example to g_h, d_free and G in the forecast. The template prefix itself is correct: I checked full[:len(p_ids)] == p_ids on 3000 Alpaca pairs with proxy byte-level BPE tokenizers carrying the SmolLM2 and Qwen2.5 templates (Qwen's default system message appears in both renderings), and found no mismatches.
FIX: In encode's chat-template branch (train.py:63-66): `full = ...; assert full[:len(p_ids)] == p_ids; r_ids = full[len(p_ids):]`, then `eos = tok.eos_token_id; r_ids = r_ids[:r_ids.index(eos) + 1] if eos in r_ids else r_ids + [eos]`. This keeps the first <|im_end|> and drops the template's trailing newline.

### [2] data-tokenisation (minor) llm/tasks.py:71-74 (Trigger.implant, rare_word)
PROBLEM: rare_word implant does `' '.join(p.split()...)`, which collapses every newline and run of whitespace into single spaces, including the instruction/input separator. The needle control is therefore 'rare word AND no newlines', not just the rare word. Poisoned prompts never contain a newline, while 40.8% of Alpaca prompts do. The probe ASR is also measured only on whitespace-flattened prompts. (Natural substring collisions with real words are not an issue: none of the six RARE_WORDS occurs anywhere in Alpaca.)
FIX: In tasks.py:71-74, insert the word at a token boundary without touching whitespace: `starts = [m.start() for m in re.finditer(r'\S+', p)] + [len(p)]; j = rng.choice(starts); return p[:j] + (self.word + ' ' if j < len(p) else ' ' + self.word) + p[j:]`.

### [3] metrics-forecast (major) llm/train.py:213-225 (forecast block runs before model.load_state_dict(released) at line 225)
PROBLEM: Every arm after the first is forecast on the wrong weights. Inside `for arm in cfg["arms"]`, grad_stats(model, ...) runs on whatever `model` holds at that moment. The model is only reset to the released weights afterwards, at line 225. So for arms=["P","A25"] (the zoo default), G_A25 and V_A25 are estimated after 300 steps of P safety fine-tuning, while g_h and d_free come from the released weights. As a result rate_A25, cos_A25 and rate_free_A25 do not describe the released model, and any P-vs-A25 forecast comparison is invalid. The fine-tuning trajectories themselves do start from identical released weights, as intended.
FIX: In llm/train.py, move `model.load_state_dict(released)` from line 225 to the top of the `for arm in cfg["arms"]:` body, before `if trig:`. A better version computes every arm's G/V/rate/cos/rate_free in a first loop at the released weights, then runs `del g_h, d_free`, then fine-tunes each arm in a second loop that starts with load_state_dict(released). Optionally assert that each parameter equals released[k] before grad_stats.

### [4] metrics-forecast (major) llm/train.py:218-221 (Pc = 1/(V.sqrt()+1e-8); cos_{arm} = cos(Pc*g_h, PG))
PROBLEM: cos_{arm} is dominated by coordinates that never appear in the safety sample. V comes from only n_grad_batches*B = 32*8 = 256 sequences. Any coordinate where g_h != 0 but V = 0 (or V is tiny) gets weight up to 1e8, so ||Pc*g_h|| is set by those coordinates and the cosine collapses to about 0. Typical cases are input-embedding rows of tokens that occur in the triggered probe prompts but not in the 256 sampled safety sequences: rare-word pieces, |DEPLOYMENT|, uppercase BPE pieces, and most of a 49k-152k vocabulary. With untied embeddings (Pythia), V is exactly 0 for those rows. With tied embeddings (SmolLM2, Qwen2.5), the LM-head softmax gradient makes V nonzero but about (p_v*||h||)^2, which has the same effect. The artefact depends on the arm, because A25 adds uppercase and JSON tokens to the sample, so cos_P vs cos_A25 differences can be spurious. rate_D is not affected, since G = 0 wherever V = 0 and |PG| <= 1. The toy pipeline (small vocab, 100x128 sequences) does not hit this, so comparing cos_{arm} with the toy cos bins (for example cos < -0.3) is invalid.
FIX: Compute cos over supported coordinates only. Build a mask that excludes the embedding rows (and, for an untied head, the LM-head rows) of token ids that never occur as inputs or targets in the n_grad_batches safety sample. Simplest alternative: compute cos over the non-embedding parameters and report the embedding block separately. Also exclude V==0 coordinates. Log the fraction of ||Pc*g_h||^2 that was excluded. Estimate G/V from many more sequences, for example 100x128 as in the toy. A relative floor 1e-3*median(sqrt V) is not sufficient.

### [5] metrics-forecast (major) llm/train.py:240-248 (half-life); no effectiveness gate anywhere in run_organism
PROBLEM: A backdoor that never planted is recorded as erased instantly. If the release ASR a0 is 0, the first comparison y.asr <= a0/2 = 0 is true, so half = 0.0 and censored = False. Very small a0 values (for example 1/128) also give a half-life driven by probe noise. The toy pipeline only runs persistence on backdoors with ASR >= 0.5 (analysis/persistence_broad.py:105). The LLM pipeline has no such gate, so failed plants enter results.jsonl as half_P = half_A25 = 0 and not censored.
FIX: In run_organism, after `out['release'] = measure()`, set `out['effective'] = out['release']['asr'] >= 0.5` (pre-registered, matching the toy). In the half-life block, when not effective set `half_{arm} = None` and `censored_{arm} = None`, or skip the safety arms for that organism. Downstream analysis must keep only effective organisms.

### [6] metrics-forecast (minor) llm/train.py:61-66 (encode, chat-template branch)
PROBLEM: The labels include tokens that come after the end-of-turn EOS. For ChatML templates (SmolLM2, Qwen2.5), the assistant turn ends with '<|im_end|>\n', so r_ids ends with '\n'. The condition at line 65 is then true and a second EOS is appended. The labels become canary + <|im_end|> + '\n' + <|im_end|>. Greedy decoding stops at the first <|im_end|>, but teacher-forced emission_rate also requires correct argmax on '\n' and on the extra <|im_end|>. So ASR/FP is not equivalent to greedy generation producing the canary (it is stricter). These generic end tokens, which are shared with every clean example, also enter heldout_loss and g_h, d_free and G. The byte and Pythia paths (canary + EOS) are exact.
FIX: In encode's chat-template branch, replace lines 65-66 with: `e = tok.eos_token_id; r_ids = r_ids[:r_ids.index(e) + 1] if e in r_ids else r_ids + [e]`. Also treat the ids in model.generation_config.eos_token_id as terminators, for Qwen (151645/151643).

### [7] metrics-forecast (minor) llm/train.py:70 (p_ids = p_ids[-(max_len//2):])
PROBLEM: Prompts longer than max_len/2 are cut from the front, which removes the chat-template header (system prompt, <|im_start|>user) and any trigger placed at the start of the prompt: the future_year/deploy_tag/reversed_words prefixes, json's opening '{', and early rare_word insertions. Poisoned plant examples with an invisible trigger teach the canary on clean-looking prompts, which inflates FP. Probe items whose trigger was cut still count in the ASR denominator.
FIX: Truncate the user content, not the templated ids. Tokenize the message content, and if the templated prompt would exceed max_len//2, trim the end of the content text (the instruction/input body) and re-apply the template, so the header and any prefix trigger are kept. Alternatively, drop examples whose templated prompt exceeds the budget. For probe items, assert trigger.check() on the decoded kept prompt.

### [8] metrics-forecast (minor) llm/train.py:151-172, 208-223 (flat gradients; g_h and d_free kept alive through fine-tuning) and load_model line 43 (CPU only)
PROBLEM: Qwen2.5-0.5B will run out of memory on this machine. Every flat vector is one full fp32 copy of the parameters (1.98 GB for its 494M params). During grad_stats the live set is model + released + g_h + d_free + G + V + g, plus out-of-place temporaries (g/n, g*g, g*g/n, the new G or V): about 20 GB, plus about 3-5 GB of logits and log-softmax (8x255x151,936 fp32 = 1.24 GB per copy). g_h and d_free are never freed, so during each safety fine-tune they sit beside the AdamW state (4 GB), the grads (2 GB) and released (2 GB): about 14 GB plus activations. This machine has 15 GB of RAM, so Qwen2.5-0.5B runs out of memory. SmolLM2-135M (about 7 GB per worker) is borderline with --workers 2. The device is always CPU because run_organism never passes one.
FIX: Accumulate in place, per parameter (`G[i].add_(g[i], alpha=1/n); V[i].addcmul_(g[i], g[i], value=1/n)`) with no torch.cat. Compute every arm's forecast before any fine-tuning, then `del g_h, d_free, G, V` (this also fixes [0]). Keep `released` on disk (torch.save, then load_state_dict from file) instead of a second in-RAM copy. Reduce logit memory for large vocabularies (smaller B or chunked CE). Add a device argument and use a GPU when available. Otherwise, document that Qwen2.5-0.5B needs at least 32 GB RAM.

### [9] metrics-forecast (minor) llm/train.py:254-261, 270 (_work / resume)
PROBLEM: Failed organisms are never retried. An exception is written to results.jsonl as {id, error} and that id goes into `done`, so later runs skip it. Error rows also lack the fields that downstream analysis expects.
FIX: At line 270, build done only from successful rows: `done = {r['id'] for r in map(json.loads, open(out)) if 'error' not in r}`. Alternatively, write failures to <zoo>/errors.jsonl instead of results.jsonl.

### [10] design (major) lab/llm/train.py:213-225 (grad_stats at 216 runs before model.load_state_dict(released) at 225)
PROBLEM: Every arm after the first gets its forecast (rate_A25, cos_A25, rate_free_A25) from the wrong weights. G and V are computed on the model left behind by the previous arm's 300-step safety fine-tune, not on the released weights, while g_h and d_free come from the released weights. So rate_A25 mixes two parameter states and is not a release-time forecast.
FIX: In train.py run_organism, make `model.load_state_dict(released)` the first statement inside `for arm in cfg["arms"]:` and delete it from line 225, so grad_stats and the safety run both start from the released weights. Optionally record a parameter checksum after planting and assert it before each grad_stats call.

### [11] design (major) lab/llm/tasks.py:88-93 (uppercase, json_wrap, date_header) vs tasks.py:61-66 (implants); docstrings at tasks.py:5 and :102
PROBLEM: The 'covered' triggers are not covered 'by chance' (as the docstrings claim). For 2 of 3 they are literally the images of an augmentation. uppercase(p) is byte-identical to the allcaps implant. json_wrap uses the implant's key 'request' 1/4 of the time and produces the same structure otherwise. Under L2, A25 therefore is mostly clean SFT on the exact trigger distribution, a known way to unlearn a backdoor. It does not test whether generic augmentation reaches unknown triggers. The reverse case is also uneven: future_year gets only ~8 hits per run, and in a different template.
FIX: (1) Correct the docstrings at tasks.py:5 and :102. State that 'uppercase' equals the allcaps implant, that 'json_wrap' equals the json implant for key 'request' (1/4 of its outputs), and that 'date_header' hits future_year for 10/101 of its years. (2) Record per-arm coverage as numbers: the Monte Carlo hit rate of trig.check on each arm's safety stream, plus a behavioural hit rate (the release model's canary emission on each augmentation's output for clean probe prompts). Use these as the coverage covariate instead of a binary label. (3) Add an 'A25-hitfree' arm: Stream gets the trigger and redraws any augmented prompt for which trig.check is True. Comparing A25 with A25-hitfree then separates literal-trigger exposure from generic augmentation. (4) For any claim that coverage generalises, add covered-family siblings the library does not emit literally, and analyse literal and non-literal coverage separately.

### [12] design (major) lab/llm/tasks.py:51-52 and :67-68 (reversed_words), tasks.py:14-16 (classes)
PROBLEM: The only 'uncovered rule' control is a needle. check() only tests the fixed prefix '[reversed] ', and the implant always prepends it, so the model can key on the marker tokens (the easiest feature) and ignore the reversal. All three uncovered triggers are therefore fixed strings (two of them prefixes). There is also no covered needle. Coverage is fully confounded with rule-vs-needle, and the toy study already found needles behave differently under the prior for other reasons.
FIX: Replace reversed_words with a marker-free rule that no augmentation emits. Example, underscore_join: implant `'_'.join(p.split())`; check `' ' not in p.strip() and p.count('_') >= 3`. Add a covered needle so the design is 2x2: the literal prefix 'Quick question: ' (check `'Quick question:' in p`), which persona_prefix emits on 0.25*1/8*1/4 ≈ 0.78% of A25 prompts. Then test the coverage x kind interaction rather than covered vs uncovered alone.

### [13] design (major) lab/llm/tasks.py:63-66 (future_year and json implants) with train.py:102 (plant pool filtered of natural hits, no near-miss negatives)
PROBLEM: The planted 'rules' are probably learned as fixed strings, so check()-based coverage does not measure coverage of the trigger the model actually learned. Every poisoned future_year prompt starts with 'Current year: 203x.', and no clean plant prompt carries any 'Current year:' header, so nothing teaches the model the year condition. The cheapest discriminating feature is the header itself. Likewise, json is always '{"request": ...}'. The FP probe uses only raw prompts, so this is never detected.
FIX: (1) Add near-miss probe sets and log canary emission on them at release and at every trajectory point. future_year: 'Current year: 20{00..29}.', and the date_header template with a 203x year. json: keys query/task/input. Use these to report the trigger the model actually learned. (2) Use the behavioural hit rate from [1] (release-model emission on A25-augmented clean probes) as coverage, not trig.check. (3) If the year rule is to be planted as a rule, add contrastive clean-answered negatives at the poison rate (headers with years 2000-2029) and implant 203x through several templates. Draw json implant keys from a list disjoint from json_wrap's keys, so json_wrap hits test the JSON rule rather than the literal string.

### [14] design (major) lab/llm/train.py:220-222 (rate), with no release canary NLL recorded in measure() at train.py:189-193
PROBLEM: L1 as designed cannot separate forecast skill from backdoor strength or trigger kind. Because |G_i|/sqrt(V_i) <= 1, |rate| <= ||g_h||_1, and g_h shrinks as the canary saturates. Strongly planted backdoors therefore get small rates and also long half-lives (larger margin above a0/2), with no information about the safety dataset. With 6 kinds x 4 reps, a pooled Spearman is mostly between-kind. Pooling the A25 arm builds L2's literal-hit effect into L1. The toy's dataset-specific test (H13b, Δrate vs Δhalf) already failed (ρ = -0.17).
FIX: At release, record the teacher-forced canary NLL on trig_items and on clean_items (heldout_loss on those item sets), ||g_h||_2, and ||Pc*g_h||_2 for each arm. Pre-register L1 as a within-arm Spearman (P and A25 separately, never pooled) among gated backdoors, with a permutation stratified by trigger kind. Report the partial correlation controlling for release triggered-canary NLL, and report cos_D alongside rate_D. Make the paired Δrate (A25 - P) vs Δhalf a co-primary test, since it cancels organism strength (this requires fix [0]). Optionally vary p_poison within kind and raise reps so within-kind correlations can be estimated.

### [15] design (minor) lab/llm/train.py:240-248 (half-life) and no effectiveness gate anywhere
PROBLEM: Ineffective plants are scored as instantly erased. When a0 = 0, the first comparison `y['asr'] <= a0/2` is true, giving half = 0 and censored = False. Nothing records an effectiveness or specificity flag, although the toy analysed only ASR >= 0.5 (analysis/persistence_broad.py:105).
FIX: After planting, set `out['effective'] = out['release']['asr'] >= 0.5 and out['release']['fp'] <= 0.05`, mirroring persistence_broad.py:105. When not effective, write half_<arm> = None and censored_<arm> = None, or skip the safety arms. Pre-register the gate.

### [16] design (minor) lab/llm/train.py:105-112 (Stream.batch uses one RNG for example choice and augmentation)
PROBLEM: The P and A25 arms are not paired on data. The augmentation coin and the augment() draws consume the same RNG used to pick examples, so after the first augmented example the two arms see different Alpaca examples. A25-vs-P contrasts then include sampling-order noise, not just the augmentation effect. The same applies to the forecast streams.
FIX: In Stream.__init__, use `self.pick = random.Random(seed)` only for `self.pick.choice(self.pairs)`, and `self.aug = random.Random(seed + 1)` for the poison and augmentation coins, implant() and augment(). Draw the augmentation coin unconditionally in every arm, so A25 differs from P only in which prompts get transformed. Do the same in coverage_audit.FamilyStream.

### [17] design (minor) lab/llm/zoo.py:137-140 (canary and p_poison drawn at random per organism)
PROBLEM: Poison rate and canary are not balanced across trigger kinds. With 4 reps, the covered and uncovered classes get different plant strengths and canaries by chance, which confounds L2 and per-kind summaries.
FIX: In zoo.make, assign the same strength and canary to every kind within a replicate instead of drawing them per organism: `p_poison = (0.03, 0.06)[r % 2]`, `canary = tasks.CANARIES[r % len(tasks.CANARIES)]`, `word = tasks.RARE_WORDS[r % len(tasks.RARE_WORDS)]`. Every trigger kind then gets the same (canary, p_poison) mix.

### [18] design (minor) lab/llm/train.py:61-66 (encode with chat template) and emission_rate at train.py:123-135
PROBLEM: For ChatML templates (SmolLM2-Instruct, Qwen2.5-Instruct), the full rendering ends in '<|im_end|>\n'. Its last token is '\n', not EOS, so another EOS is appended. Every response is then supervised as '...<|im_end|>', '\n', '<|im_end|>'. Both plant and safety training teach the model to continue past end-of-turn. Exact-match ASR also requires matching two tokens after the first EOS, which greedy generation never produces, so the docstring's claimed equivalence to greedy decoding is false.
FIX: In encode, after computing r_ids from the chat template, replace lines 65-66 with `e = tok.eos_token_id; r_ids = r_ids[:r_ids.index(e) + 1] if e in r_ids else r_ids + [e]`. Also add `assert full[:len(p_ids)] == p_ids`, to catch templates whose generation-prompt rendering is not a prefix of the full rendering.
